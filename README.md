# PushUp Tracker — Telegram-бот для учёта отжиманий

Бот обрабатывает Telegram-видеокружочки с помощью Google Gemini, хранит результаты в SQLite и автоматически публикует ежедневный итог. Поддерживает ручной ввод при ошибке анализа, настройку доступа, админские корректировки и диагностику.

## Основные возможности

- Видеокружочки анализируются через Gemini API (`vision.py`), результаты сохраняются за дату исходного сообщения.
- Если анализ не удался или модель не уверена, бот предлагает автору ввести число **от 0 до 1000 в течение 15 минут** с момента появления запроса.
- Ручной ввод учитывается только при ответе на сообщение-запрос или исходный кружочек, только от автора кружочка, один раз. Строки, SQL, Unicode-цифры, дроби и отрицательные числа не принимаются.
- **`/stats` и `/today`** показывают только количество отжиманий за текущий день, включая нули для участников с предыдущими результатами. Штрафы и статусы выполнения в этих командах не отображаются.
- **`/yesterday`** показывает подробные итоги закрытого предыдущего дня, выполнение норм, ручной ввод и назначенные штрафы.
- Автоотчёт за вчера публикуется в `00:00` в часовом поясе `REPORT_TIMEZONE`.
- **`/debug`** доступен только `OWNER_ID` и только в личных сообщениях: состояние SQLite, число записей/групп, модели, сроки ручного ввода, следующий отчёт и т. д. Токены и ключи не выводятся.
- Админские команды в `/help` и Telegram-меню команд не публикуются.

## Правила штрафов

1. До первого сохранённого результата или админской корректировки участник не учитывается для штрафов. В дальнейшем отсутствие результатов в какой-либо день считается нулём.
2. В течение текущего дня никто не штрафуется *за нехватку отжиманий именно сегодня*: этот день ещё не закрыт.
3. После завершения дня, если его итог ниже действующей нормы, на **следующий** день назначается `DAILY_TARGET × 2 + 10` (например, при норме 100 — 210).
4. Если штрафная норма не выполнена, на следующие сутки снова 210, без накопления штрафа. Если выполнена — последующие сутки снова обычная норма.
5. Исторические корректировки владельца пересчитывают цели в будущих отчётах. Уже отправленные сообщения автоматически не редактируются.

**Пограничный случай полуночи:** если запрос ручного ввода создан в 23:59, он действителен до 00:14:00 (не включая этот момент). Введённый после полуночи результат записывается за дату исходного кружочка. Поэтому уже отправленный в 00:00 отчёт может устареть; `/yesterday` пересчитает данные при следующем запросе. Для окончательной фиксации дня владелец может применить `/setpushups`.

## Пользовательские команды

| Команда | Назначение |
|---|---|
| `/start` | Краткая информация о боте; в группе регистрация чата |
| `/help` | Все доступные обычным участникам команды, без админских |
| `/stats`, `/today` | Короткая статистика: отжимания за сегодня |
| `/yesterday` | Подробные итоги за вчера, штрафы по завершённому дню |
| `/rules`, `/pravila` | Правила из `rules.txt` |
| `/myid` | Твой Telegram ID (только в личке) |

Бот принимает видеокружочки (`video_note`) в разрешённых группах. При неудачном анализе отвечает `ForceReply` с запросом числового результата; ручной ответ помечается ✍️. В личке видео анализируется отдельно для диагностики, без записи в статистику.

## Команды владельца

Команды управления доступом работают **только в личке `OWNER_ID`**:

| Команда | Назначение |
|---|---|
| `/access` | Разрешённые группы и пользователи |
| `/allowgroup CHAT_ID` | Разрешить группу |
| `/denygroup CHAT_ID` | Запретить группу и выйти |
| `/allowuser USER_ID` | Разрешить личные сообщения |
| `/denyuser USER_ID` | Запретить личные сообщения |
| `/debug` | Сводная диагностика состояния бота (только в личке) |

Дневные корректировки выполняются **только владельцем**, в том числе в разрешённой группе:

```text
# В группе в ответ на сообщение участника:
/setpushups 150 [YYYY-MM-DD]
/clearpushups [YYYY-MM-DD]

# В группе по User ID:
/setpushups USER_ID 150 [YYYY-MM-DD]
/clearpushups USER_ID [YYYY-MM-DD]

# В личке владельца:
/setpushups CHAT_ID USER_ID 150 [YYYY-MM-DD]
/clearpushups CHAT_ID USER_ID [YYYY-MM-DD]
```

`/setpushups` задаёт **итог**, а не прибавляет число к видео. Допустимы целые числа `0..100000`. Если дата не указана, используется сегодняшний день по `REPORT_TIMEZONE`. Данные исходных видео не удаляются; `/clearpushups` отменяет переопределение. Если пользователь не найден в базе, бот попытается получить его имя из Telegram.

## Установка

Требуется сервер с Docker и Docker Compose. Существующий `compose.yaml` можно оставить без изменений.

```bash
git clone https://github.com/exname69/pushup-tracker.git
cd pushup-tracker
cp .env.template .env
# Отредактируй .env, укажи токен, Gemini API ключ, OWNER_ID и белые списки
sudo docker compose up -d --build
sudo docker compose logs -f --tail=100 bot
```

Пример основных параметров `.env`:

```dotenv
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
GEMINI_MODEL=gemini-3.5-flash-lite
REPORT_TIMEZONE=Europe/Zurich
DAILY_TARGET=100
CASH_FINE=500
DB_PATH=./data/pushups.sqlite3
OWNER_ID=123456789
ALLOWED_CHAT_IDS=-1001234567890
ALLOWED_USER_IDS=111111111,222222222
```

Переменные `GEMINI_MODEL`, `REPORT_TIMEZONE`, `DAILY_TARGET`, `CASH_FINE`, `DB_PATH`, `OWNER_ID`, `ALLOWED_CHAT_IDS`, `ALLOWED_USER_IDS` описывают используемые модель, дату отчёта, норму, денежный штраф в правилах, SQLite, владельца и белые списки. Не добавляйте `.env` в Git. `rules.txt` перечитывается при каждом запросе; поддерживает `{DAILY_TARGET}`, `{PENALTY_TARGET}`, `{REPORT_TIMEZONE}`, `{CASH_FINE}`. Путь можно переопределить переменной `RULES_PATH`.

Для работы бота в группах при необходимости отключите Privacy Mode в BotFather (`/setprivacy` → `Disable`). Группа должна быть в `ALLOWED_CHAT_IDS` или разрешена через `/allowgroup`. Бот покидает другие группы. Белые списки из SQLite имеют приоритет над `.env`.

## Хранение и миграция

Таблицы: `chats`, `members`, `video_counts`, `daily_overrides`, `reports`, `pending_manual`, `access_rules`. Миграция создаёт недостающие `pending_manual`, `access_rules`, колонку `is_manual` и добавляет срок `expires_at_utc` в `pending_manual`, если его ещё не было.

**Старые ожидающие ручного ввода запросы без срока действия намеренно считаются просроченными.** Существующие результаты, чаты и корректировки не удаляются. Старые просроченные запросы очищаются при плановой уборке или первом ответе на них. Для обновления сделайте SQLite backup и сохраните Docker volume с `data/`. Для активной БД с WAL используйте штатный SQLite backup, а не копирование одного `.sqlite3`.

## Проверка и обновление

Положите все файлы пакета обновления в корень клона, сохранив пути (`tests/` тоже). `storage.py`, `vision.py`, `requirements.txt`, `rules.txt`, `compose.yaml` менять не требуется.

```bash
python -m unittest discover -s tests -v
sudo docker compose build bot
sudo docker compose up -d --no-deps --force-recreate --no-build bot
sudo docker compose logs -f --tail=100 bot
```

Тесты `tracker_core.py` используют стандартную библиотеку Python и SQLite. Полная сборка и запуск Telegram-бота требуют зависимостей из `requirements.txt`. Убедитесь, что одновременно работает только один экземпляр polling-бота.

Новая версия `Dockerfile` копирует в образ модуль `tracker_core.py`; без этого образ запустится с ошибкой импорта. Лимит Telegram-сообщения — 4096 символов. Результаты приватного видеоанализа никогда не попадают в групповую статистику.
